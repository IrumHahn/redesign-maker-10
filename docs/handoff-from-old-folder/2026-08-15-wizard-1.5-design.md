# 리디자인 마법사 1.5 설계 문서

날짜: 2026-08-15
상태: 사용자 승인 대기

## 배경과 철학

사용자 피드백 결과, 1.0이 3.0(상세페이지 마법사)보다 "더 상세페이지스러운" 결과를 냈다. 원인 분석:

- 3.0은 한국 PDP 정보 공식을 StoryBrand 판매 서사로 교체 → 광고 랜딩처럼 읽힘
- 통이미지 모드에서 CTA 전면 금지 → "팔려는 페이지" 인상 약화
- 히어로→확장 2단계 생성 → 전역 설계 약화, 전환 문장 위주 카피
- 프롬프트 비대화(수십 개 강제·금지 규칙) → 주의력 희석
- AI가 한글 타이포·레이아웃까지 렌더링 → 품질 불안정, 통일감 저하

**1.5 고정 철학: 가볍고 심플하게. 핵심 결과(팔리는 블루프린트 + 쓸 수 있는 섹션 이미지)만 잘 나오게.**

- 원샷 블루프린트 + PDP 정보 공식(체크리스트/베네핏3/근거 3단/CTA 4회) 유지
- 프롬프트는 짧고 템플릿 중심 — 규칙 쌓기 금지
- BYOK(사용자 Gemini API Key) + Vite 정적 배포, 서버 없음
- 이미지는 텍스트 없는 광고사진, 카피는 앱이 Canvas로 합성
- **지식파일 등록 기능 폐지** (운영자 플레이북, 사용자 지식파일 모두). 검증된 전환 인사이트는 필요 시 템플릿 규칙 1~2줄로 승격하는 방식으로만 반영

## 확정된 요구사항

- 핵심 가치: 카피/기획 품질 (사용자 피드백 근거)
- 최종 결과물: 카피가 합성된 섹션 이미지 ZIP
- 배포: 현행 BYOK 유지

## 기능 설계

### 1. 치명 버그 수정
`src/components/BlueprintEditor.tsx:56`의 `process.env.API_KEY` 참조 제거. App에서 `apiKey`를 props로 전달해 에디터 내 이미지 생성이 실제 동작하게 함.

### 2. 카피 인라인 편집
- 에디터의 헤드라인/서브헤드/불릿/CTA 클릭 시 입력 필드로 전환, 섹션 상태에 저장
- 수정값은 텍스트 합성 미리보기에 즉시 반영
- 섹션당 "카피 다시 제안" 버튼 1개: 해당 섹션만 짧은 프롬프트로 재생성(Flash 모델, 전체 재분석 아님)

### 3. 프롬프트 소폭 보강 (3.0에서 차용하는 유일한 것)
기존 1.0 분석 프롬프트에 3~4줄만 추가:
- 원본 이미지·사용자 입력에 없는 브랜드명/수치/인증/효능 날조 금지
- visible copy에 제작자용 설명문("이 섹션은...") 금지

이 이상의 규칙 추가는 하지 않는다.

### 4. 텍스트 합성 렌더러 (핵심 신규)
- Canvas 2D로 배경 이미지 위에 카피 렌더링, Pretendard 웹폰트 번들
- 섹션 역할별 레이아웃 템플릿 3종:
  - 히어로형: 하단 스크림 + 대형 헤드라인
  - 정보형: 상단 헤드라인 + 불릿 칩
  - CTA형: 중앙 정렬 + 강조 배지
- 톤 프리셋(기존 7종)에 따라 색상·굵기만 변경, 폰트 패밀리는 1종 고정
- 에디터에서 실시간 미리보기 + 템플릿 전환 토글 + "텍스트 없이" 옵션

### 5. 일괄 생성 + ZIP 내보내기
- "전체 섹션 이미지 생성": 순차 생성(429 회피), 섹션별 진행 표시, 실패 섹션만 개별 재시도
- "ZIP 다운로드": 합성 완료 이미지를 `01_히어로.png` 순번 파일명으로 묶음 (JSZip, 클라이언트 처리)
- 블루프린트 전체 마크다운 클립보드 복사 (외주/디자이너 전달용)

### 6. 세션 복원
블루프린트 JSON + 원본 이미지를 localStorage 저장(생성 이미지는 용량상 제외). 새로고침 시 "이전 작업 이어하기" 제안.

## 하지 않는 것 (1.5 범위 제외)

- 지식파일 등록 (폐지 확정), 제품 사실 입력 확장
- 판매 스타일 선택, 히어로 확장 플로우
- 고객 후기 업로드/분석
- 통이미지 모드 (AI가 텍스트를 이미지에 렌더링)
- 어드민, 버그리포트 위젯, 서버 인프라
